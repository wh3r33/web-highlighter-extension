Минимальный, локальный и понятный инструмент для учебных заметок, исследования материалов и сбора цитат. Расширение работает без серверов, без аналитики и без фреймворков: только Manifest V3, HTML, CSS и JavaScript.

## Архитектура

Расширение разделено на три независимых контекста Chrome Extension: content script, popup и background service worker.

```text
Веб-страница
   |
   | 1. Пользователь выделяет текст
   v
Скрипт страницы
   |
   | chrome.runtime.sendMessage(...)
   v
Фоновый service worker
   |
   | chrome.storage.local
   v
Локальное хранилище Chrome
   ^
   | chrome.runtime.sendMessage(...)
   |
Popup
```

| Часть | Файл | Ответственность |
|---|---|---|
| Скрипт страницы | `content/content.js` | Отслеживает выделение, показывает панель, создает подсветку, восстанавливает выделения на странице. |
| Popup | `popup/popup.html`, `popup/popup.css`, `popup/popup.js` | Показывает архив, поиск, группировку, заметки, удаление, открытие источника и экспорт. |
| Фоновый service worker | `background.js` | Принимает сообщения через `chrome.runtime` и читает/записывает данные в `chrome.storage.local`. |
| `manifest.json` | `manifest.json` | Описывает разрешения, иконки, popup, service worker и content scripts. |

<details>
<summary><strong>Как движутся данные</strong></summary>

1. Скрипт страницы формирует объект выделения: текст, URL, заголовок страницы, категорию, заметку и timestamp.
2. Скрипт страницы отправляет `SAVE_HIGHLIGHT` в background service worker.
3. Background service worker сохраняет массив выделений в `chrome.storage.local`.
4. Popup запрашивает `GET_HIGHLIGHTS` и рендерит сохраненный архив.
5. Удаление и обновление заметок проходят через те же runtime-сообщения.

</details>

## Подготовка к защите

Этот раздел помогает коротко и уверенно объяснить проект на устной защите: где выполняется код, зачем нужен `manifest.json`, как сохраняются данные и какие ограничения есть у Chrome-расширений.

### 1. Контексты расширения

В Chrome-расширении код не выполняется в одном общем месте. Проект разделен на несколько контекстов, потому что у страницы, popup и фонового процесса разные права и разные задачи.

| Контекст | Файл | Где выполняется | За что отвечает |
|---|---|---|---|
| Content script | `content/content.js` | Внутри обычных веб-страниц, которые открывает пользователь | Видит выделенный текст на странице, показывает плавающую панель, создает и восстанавливает подсветку. |
| Popup | `popup/popup.js` | Только внутри окна расширения, которое открывается по нажатию на иконку | Показывает список сохраненных выделений, поиск, заметки, удаление и экспорт. |
| Background service worker | `background.js` | В фоновом контексте расширения | Координирует сообщения между частями расширения и работает с `chrome.storage.local`. |

`content/content.js` и `popup/popup.js` - это разные JavaScript-файлы. Они не являются одним и тем же кодом, потому что работают в разных местах:

- `content/content.js` запускается на веб-странице и может взаимодействовать с ее DOM.
- `popup/popup.js` запускается только в popup расширения и управляет интерфейсом архива.
- `background.js` не рисует интерфейс на странице, а принимает сообщения и сохраняет данные.

Chrome разделяет эти контексты по соображениям безопасности. Content script имеет доступ к содержимому страницы, popup имеет доступ к интерфейсу расширения, а background service worker выполняет общую координацию. Такое разделение уменьшает риск случайного доступа к лишним данным и делает архитектуру расширения понятнее.

### 2. `manifest.json`

`manifest.json` - главный конфигурационный файл Chrome-расширения. Chrome читает его при установке расширения и понимает, какие файлы запускать, какие права нужны и как показывать расширение в браузере.

| Поле | Значение в проекте | Объяснение |
|---|---|---|
| `manifest_version` | `3` | Указывает, что проект использует Manifest V3. Это современный формат Chrome-расширений. |
| `name` | `Учебный маркер` | Название расширения, которое пользователь видит в Chrome. |
| `version` | `1.0.0` | Версия проекта. Нужна для обновлений и контроля изменений. |
| `description` | Русское описание проекта | Кратко объясняет, что делает расширение. |
| `permissions` | `storage`, `tabs` | `storage` нужен для сохранения выделений в `chrome.storage.local`, а `tabs` помогает работать с вкладками и источниками. |
| `host_permissions` | `<all_urls>` | Разрешает расширению работать на разных сайтах, где пользователь может выделять текст. |
| `background.service_worker` | `background.js` | Указывает фоновый service worker, который принимает сообщения и сохраняет данные. |
| `action` | `default_title`, `default_popup`, `default_icon` | Описывает кнопку расширения в панели Chrome, popup-файл и иконки для кнопки. |
| `icons` | `icons/icon16.png`, `icons/icon32.png`, `icons/icon48.png`, `icons/icon128.png` | Задает иконки расширения разных размеров. |
| `content_scripts` | `matches`, `js`, `css`, `run_at` | Говорит Chrome, что на подходящие страницы нужно подключать `content/content.js` и `content/content.css`. |

`host_permissions: ["<all_urls>"]` означает, что расширение получает право запускать content script на большинстве обычных сайтов. Это нужно проекту, потому что пользователь может захотеть сохранить учебный фрагмент не только с одного сайта, а с разных страниц: статей, документации, учебных материалов и справочников.

Это серьезное разрешение, потому что теоретически расширение с таким доступом может видеть содержимое многих страниц. На банковских, почтовых, рабочих и личных страницах выделенный текст может быть чувствительным. Поэтому разработчик обязан использовать такое разрешение аккуратно и не собирать лишние данные.

В этом проекте данные не отправляются на внешние серверы. Расширение сохраняет только то, что пользователь сам выделил и решил сохранить. Сохранение происходит локально через `chrome.storage.local`.

### 3. `chrome.storage.local` и `localStorage`

В проекте используется `chrome.storage.local`, потому что это хранилище специально предназначено для Chrome-расширений.

| Вариант хранения | Почему подходит или не подходит |
|---|---|
| `chrome.storage.local` | Подходит, потому что доступен частям расширения через Chrome API: popup, background service worker и content script могут работать с данными расширения. |
| `localStorage` | Не подходит как основное хранилище, потому что привязан к конкретной странице или конкретному контексту. Данные из `localStorage` одной страницы не являются общим надежным хранилищем всего расширения. |

Если использовать `localStorage` на веб-странице, данные будут относиться к этой странице, а не к расширению в целом. Popup и background service worker не должны зависеть от хранилища конкретного сайта. Для расширения важно иметь одно локальное место, где лежат все сохраненные выделения. Поэтому используется `chrome.storage.local`.

### 4. Передача данных между popup и content script

Сохранение выделения происходит по цепочке. Ее удобно объяснять как маршрут данных от страницы до локального хранилища.

1. Пользователь выделяет текст на веб-странице.
2. `content/content.js` обнаруживает выделение.
3. Рядом с выделенным текстом появляется плавающая панель.
4. Пользователь нажимает кнопку сохранения.
5. Нажатие обрабатывается в контексте content script, потому что кнопка находится поверх веб-страницы.
6. Content script подготавливает данные выделения:
   - текст;
   - URL страницы;
   - заголовок страницы;
   - категорию;
   - заметку;
   - timestamp.
7. Данные отправляются через Chrome runtime messaging.
8. `background.js` получает сообщение `SAVE_HIGHLIGHT`.
9. `background.js` сохраняет выделение в `chrome.storage.local`.
10. `popup/popup.js` запрашивает сохраненные выделения через сообщение `GET_HIGHLIGHTS` и показывает их в popup.

Главная идея: content script отвечает за работу с текстом на странице, background service worker отвечает за сохранение, а popup отвечает за отображение уже сохраненных данных.

### 5. Безопасность и ответственность

Расширение с доступом к разным сайтам теоретически может работать с выделенным текстом на многих страницах. Если пользователь находится на странице банка, почты, личного кабинета или рабочего сервиса, выделенный текст может содержать чувствительную информацию.

В этом проекте приняты такие ограничения:

- сохраняется только текст, который пользователь сам выделил;
- данные сохраняются локально в `chrome.storage.local`;
- проект не отправляет данные на внешние серверы;
- в коде нет внешней аналитики;
- широкие разрешения используются только для работы на обычных веб-страницах.

В сохраненном выделении могут храниться:

| Данные | Зачем нужны |
|---|---|
| Выделенный текст | Основное содержимое заметки. |
| URL | Позволяет вернуться к источнику. |
| Заголовок страницы | Помогает понять, откуда взят фрагмент. |
| Заметка | Позволяет добавить собственный комментарий. |
| Timestamp | Показывает время сохранения. |
| Категория | Помогает сортировать и понимать смысл выделения. |

Широкие разрешения требуют ответственности от разработчика. Нельзя сохранять больше данных, чем нужно, нельзя скрыто отправлять данные наружу и нужно ясно объяснять пользователю, что именно делает расширение.

### 6. Особые случаи

Не на всех страницах Chrome разрешает работу content script. Это нормальное ограничение браузера, а не ошибка проекта.

| Случай | Что происходит |
|---|---|
| `chrome://extensions/` | Chrome блокирует content scripts на внутренних страницах браузера, поэтому панель выделения там не появляется. |
| Страницы Chrome Web Store | Chrome ограничивает работу расширений на этих страницах, поэтому content script может не запускаться. |
| Внутренние страницы браузера | На страницах с адресами вроде `chrome://` расширение не предназначено для работы. |
| Страницы, где content scripts запрещены | Расширение не сможет увидеть выделение и показать панель. |
| Страницы со строгой CSP | Основной content script обычно запускается через механизм расширений, но отдельные действия страницы или стили могут быть ограничены политиками безопасности сайта. |
| Пустое выделение текста | Сохранять нечего, поэтому расширение не должно создавать пустую заметку. |
| Одинаковый текст в нескольких местах страницы | Восстановление основано на поиске текста, поэтому одинаковые фрагменты могут быть неоднозначными. |
| Повторное сохранение одинакового фрагмента | Проект может сохранить несколько похожих выделений, если пользователь повторяет действие. Это стоит учитывать при проверке. |
| Перезагрузка страницы | Расширение запрашивает сохраненные выделения для текущего URL и пытается восстановить подсветку по совпадению текста. |

Расширение предназначено для обычных веб-страниц: статей, документации, учебных материалов и других сайтов, где Chrome разрешает запуск content script. Восстановление подсветки работает по текстовому совпадению, поэтому при повторяющемся тексте на странице результат может быть неоднозначным.

## Установка

Деплой не требуется. Это локальное Chrome-расширение, которое загружается через режим разработчика.

1. Склонируйте репозиторий:

   ```bash
   git clone <repository-url>
   cd web-highlighter-extension
   ```

2. Откройте Google Chrome.

3. Перейдите на страницу:

   ```text
   chrome://extensions
   ```

4. Включите **режим разработчика** в правом верхнем углу.

5. Нажмите кнопку загрузки распакованного расширения.

6. Выберите папку проекта `web-highlighter-extension`.

После загрузки иконка расширения появится в панели инструментов Chrome.

> **Важно:** если Chrome показывает ошибку загрузки, проверьте, что выбран именно корень проекта, где находится `manifest.json`.

## Использование

1. Откройте обычный сайт, например статью, документацию или учебный материал.
2. Выделите фрагмент текста мышью.
3. В появившейся панели выберите категорию.
4. Нажмите **Сохранить**.
5. Добавьте заметку или сохраните без нее.
6. Откройте popup расширения через иконку в панели Chrome.
7. Ищите, редактируйте заметки, удаляйте, открывайте источник или экспортируйте выделения в файл `.md`.

## Чек-лист проверки

Используйте этот список для ручной проверки перед сдачей или релизом.

- [ ] Расширение загружается через `chrome://extensions` в режиме разработчика.
- [ ] Иконка расширения появляется в панели Chrome.
- [ ] Content script работает на обычной веб-странице.
- [ ] При выделении текста появляется плавающая панель.
- [ ] Кнопка сохранения подсвечивает текст на странице.
- [ ] Данные сохраняются в `chrome.storage.local`.
- [ ] В popup отображаются текст, источник и дата/время сохранения.
- [ ] У каждого элемента есть кнопка удаления.
- [ ] Клик по элементу открывает источник в новой вкладке.
- [ ] Пустое состояние popup показывает понятное русское сообщение.
- [ ] Поиск фильтрует сохраненные фрагменты.
- [ ] Заметку можно добавить и изменить.
- [ ] Экспорт создает файл `.md`.
- [ ] После перезагрузки страницы сохраненная подсветка восстанавливается.
- [ ] Удаленное выделение больше не появляется после перезагрузки.
- [ ] Расширение не использует `localStorage` для данных.
- [ ] Расширение не требует деплоя или внешнего сервера.

---

## Статус

Проект готов к локальной установке как распакованное Chrome-расширение. Для публикации в Chrome Web Store потребуется отдельная подготовка: описание, финальные скриншоты, проверка permissions и политика приватности.
